# Эндпоинт записи нового заказа

`POST /api/v1/order/makeOrder`

Создаёт новый заказ, проверяет наличие ингредиентов на складе по рецепту блюд,
списывает продукты и формирует стоп-лист при нехватке.

## Запрос

- **Метод:** `POST`
- **Путь:** `/api/v1/order/makeOrder`
- **Тело:** `application/json`, объект `OrderDto`
- **Авторизация:** не требуется

### Поля тела запроса

| Поле           | Тип              | Обязательное | Описание                                              |
|----------------|------------------|--------------|-------------------------------------------------------|
| `customerName` | string           | да           | Имя заказчика                                         |
| `contactPhone` | string           | да           | Контактный телефон заказчика                          |
| `format`       | enum             | да           | Формат заказа: `SelfPickup` или `Hall`                |
| `comment`      | string           | нет          | Комментарий к заказу                                  |
| `created`      | DateTime (ISO)   | нет          | Время создания; при отсутствии используется текущее   |
| `dishes`       | массив `OrderObjDto` | да      | Состав заказа (одно или несколько блюд)               |

### Поля элемента `dishes`

| Поле        | Тип     | Обязательное | Описание                    |
|-------------|---------|--------------|-----------------------------|
| `dishName`  | string  | да           | Название блюда              |
| `count`     | int     | да           | Количество порций (> 0)     |
| `dishPrice` | decimal | нет          | Цена; при создании не используется — берётся цена блюда из БД |

> Поля `payment`, `status` и `dishPrice` в ответе формируются на сервере.
> При создании заказа сумма `payment` рассчитывается по актуальной цене блюда.

### Пример тела запроса

```json
{
  "customerName": "Иван Петров",
  "contactPhone": "+7 900 123-45-67",
  "format": "Hall",
  "comment": "Без лука, приборы на двоих",
  "created": "2026-10-14T18:00:00Z",
  "dishes": [
    { "dishName": "Борщ", "count": 2 },
    { "dishName": "Стейк", "count": 1 }
  ]
}
```

## Ответы

### 200 OK — заказ принят

```json
{
  "created": "2026-10-14T18:00:00Z",
  "payment": 1350,
  "status": 0,
  "customerName": "Иван Петров",
  "contactPhone": "+7 900 123-45-67",
  "format": 1,
  "comment": "Без лука, приборы на двоих",
  "dishes": [
    { "dishName": "Борщ", "dishPrice": 350, "count": 2 },
    { "dishName": "Стейк", "dishPrice": 650, "count": 1 }
  ]
}
```

Значения `status`: `0` — `Complete`, `1` — `Cancelled`.
Значения `format`: `0` — `SelfPickup`, `1` — `Hall`.

### 400 Bad Request — заказ отклонён

Возвращается текст ошибки (`message`), например:

- `Order has no dishes` — пустой состав заказа;
- `Dish count must be greater than zero` — количество порций ≤ 0;
- `Dish not found` — блюдо из состава не найдено;
- `Order cancelled` — не хватило ингредиентов; заказ сохранён со статусом
  `Cancelled`, а затронутые блюда помечены `Available = false` (стоп-лист).

## Логика обработки

1. Проверяется состав заказа и корректность количества порций.
2. Блюда и их рецепты загружаются одним запросом (без N+1).
3. Считается суммарная потребность в продуктах по всем блюдам.
4. Потребность сверяется с доступными партиями на складе; при списании в первую
   очередь используются партии с наиболее ранним сроком годности (FEFO).
5. **Если продуктов достаточно** — они списываются, заказ сохраняется со статусом
   `Complete`.
6. **Если продуктов не хватает** — ничего не списывается, заказ сохраняется со
   статусом `Cancelled`, а блюда, чей рецепт требует дефицитных продуктов,
   получают `Available = false`.

## Пример вызова

```bash
curl -X POST http://localhost:5094/api/v1/order/makeOrder \
  -H "Content-Type: application/json" \
  -d '{
    "customerName": "Иван Петров",
    "contactPhone": "+7 900 123-45-67",
    "format": "Hall",
    "comment": "Без лука",
    "dishes": [
      { "dishName": "Борщ", "count": 2 }
    ]
  }'
```

## Связанные эндпоинты
